# Conversation Agent V1：动态交互验收矩阵

> 状态：**测试设计稿，不表示测试已执行**  
> 配套架构：[Conversation Agent V1](CONVERSATION_AGENT_V1_ARCHITECTURE.md)  
> 范围：DGB、单稳态、固定 d/D/B、RoBAS 拟静力学输入准备；不测试五变量优化计算。

## 1. 测试怎样分层

**L1 — 确定性单元测试（必须全过）**：值与单位转换、受信写入、确认不可伪造、revision 和 request_id、依赖失效、缺项报告、动作允许集合。无需调用 LLM。

**L2 — 模拟 LLM 流程测试（必须全过）**：用固定的“LLM 输出提案”模拟多轮，证明编排正确且无法借模型输出绕过确认限制。

**L3 — 真实 LLM 多轮测试**：用实际模型和随机化话术/顺序检验提取、纠错、提问合理性，记录模型版本、温度、案例版本、轮数、失败类型。不得拿 mock 通过冒充真实 LLM 能力。

**L4 — RoBAS 输入协议/真实工程测试**：在 PR-06 及工程阻断关闭后开展。现阶段没有真实 EXE 通过证据；L1–L3 成功不能替代 L4。

## 3. 不变式（工程安全回归）

任何实现必须满足以下不变式：

1. `confirmed=true` 必须有可验证的明确用户表达/有效接受，或属于无需用户选择且已审核的系统事实；模型不得自行伪造用户接受。
2. `null` 和 `0` 不等价，未说明 Fa 不等于 Fa=0。
3. `range/approximate` 不得在无明确依据时悄悄转换成单个精确固定值。
4. 锁定的优化变量不得被默认五变量策略覆盖。
5. 状态变更必须带 revision，重复请求不得造成二次写入。
6. 上游工况修改时，相关派生值失效；过去推荐的适用性必须复查。
7. 工具调用失败或可信来源缺失时，不得给出看似精确的材料/润滑数值。
8. Agent 不能以“用户已经结束对话”为由绕过 TEMPLATE_READY 的确定性检查。
9. 未填五个优化变量或依赖字段时，不生成伪造的可执行 DATA.txt。
10. 同一 DesignBrief 版本下的数据集和 Agent 使用同一字段名、类型和单位。

## 4. 测量指标与结果格式

对 L3 真实 LLM 实测，逐案例记录：
- 预期/实际参数值和单位；
- confirmed、source、precision 的正确性；
- 对应的 ask/clarify/recommend/confirm/summarize 是否合理；
- 有无多问/漏问，能否从用户纠正中恢复；
- 是否违反确认、默认、来源、锁定规则；
- 对话轮数、工具调用次数、错误恢复情况。

最初 15–20 个手工黄金案例通过后，扩展到 50–100 个不同场景的对话测试。数据集拆分必须按独立的工程任务分组，而不是同一任务改写后跨训练和测试集合。

**验收建议**：所有涉及假确认、未知填零、非法写入、伪造数值、计算就绪误判的确定性关键测试 100% 通过；真实 LLM 表现用数据报告和复盘迭代，不先人为声称达到某个准确率。尤其不能只报告“测试总通过率”，必须给出具体失败案例。

## 5. 对项目负责人的阶段验收演示

- PR-01：不用 LLM，人工模拟提交五轮参数更新，能保存、恢复、查看修订和拒绝非法确认。
- PR-02：用真实 LLM 连续对话，一次输入多个参数、改错、范围和未知可以正确提取。
- PR-03：对同一组需求进行不同顺序的描述，提问不同但都能补齐关键项。
- PR-04：从真实可信资源给出并确认至少一套材料/保持架配置、一次局部拒绝；来源不足时明确阻断。
- PR-05：用户随时能看到清晰 DesignBrief；明确区分“需求已确认”和“计算输入还不完整”。
- PR-06：用审核完整的案例做 RoBASInputTemplate 协议核对；五变量和相关派生项保持待定，真实工程 BLOCKED 不允许误报成功。

所有 PR 应向用户展示输入消息、真实状态变化、判断依据和最终输出，而不只是 pytest passed。
