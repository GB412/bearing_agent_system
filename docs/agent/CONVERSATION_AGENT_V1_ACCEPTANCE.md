# Conversation Agent V1：五工具 ReAct 动态交互验收矩阵

> 版本：v1.1（2026-11-22）；**替换**原固定流程/五动作路由的验收口径。**这是测试设计，不代表测试已运行。**  
> 参考：[ReAct 架构与工具合同](CONVERSATION_AGENT_V1_ARCHITECTURE.md)。轴承范围：DGB、单一稳态、固定 d/D/B、五优化槽留待后续。

## 1. 分层验收

| 层级 | 测什么 | 要求 |
|---|---|---|
| L1 确定性测试 | Pydantic 字段/单位/范围、唯一受信写入、revision/request_id、失效依赖、状态缺项、推荐筛选、完成度及导出 | 关键安全不变式全部通过 |
| L2 模拟工具调用链 | 给模型预设 tool calls，模拟 ReAct 工具结果、错误、重复调用、预算退出、顺序执行 | 可复现且可解释 |
| L3 真实模型多轮交互 | 模型自主问什么/怎么问、是否查工具、是否根据返回继续行动、何时结束 | 逐案例报告能力、失败和成本 |
| L4 RoBAS 工程适配 | PR-06 独立执行的 43/324 模板协议检查及验证 | **不得**被 L1–L3、工具⑤的 `brief_complete` 代替 |

首批 15–20 个人工标注黄金案例，再扩展到 50–100 个按独立设计任务划分的数据集；模型版本、提示词版本、知识库版本、配置和测试时间可追溯。

## 3. 四个基础工具与最终工具的专门测试

| ID | 用户或工具场景 | 必须达到的结果 | 阶段 |
|---|---|---|---|
| T01 | 工具①同一消息多字段批量更新 | 单次合法提交，revision 正确增长，返回实际更新和最新缺项 | PR-01 |
| T02 | 模型调用工具①时自填 `confirmed=true` | 不接收模型确认标志；根据服务端真实用户证据确定状态 | PR-01 |
| T03 | 模型引用不存在于用户原话中的 evidence_span | 拒绝非法来源，不得伪造用户数值 | PR-01 |
| T04 | `request_id` 重放 | 幂等，无重复确认/修订 | PR-01 |
| T05 | 旧 `expected_revision` 写入 | 拒绝过期修改，返回冲突和当前版本 | PR-01 |
| T06 | 工具①更新后再次调用工具② | 工具①已提供最新状态，不要求无意义重复调用；可按需独立查询 | PR-02 |
| T07 | 工具②仅提供 known/missing/pending/conflicts | **不要求**责任归属、问句列表、优先级评分；模型自主问问题 | PR-01/02 |
| T08 | 同一个设计任务，用户打乱尺寸、载荷、温度输入顺序 | Agent 问法可不同，但不漏必需项、不重复已知项 | PR-02 |

| T13 | 工具④查询到异常/重名/物性不完整的 CSV 记录 | 不能宣称已审定推荐，不创作缺的物性 | PR-04 |

## 4. ReAct 自主循环专项测试

| ID | 场景 | 正确行为 |
|---|---|---|
| R01 | 用户一次给工况并请求材料推荐 | 模型先用工具①更新，再以**新 revision**调用工具④，不使用旧温度/转速 |
| R02 | 工具④返回 NEED_INPUT | 模型停止空查，向用户问推荐必需条件 |
| R03 | 用户纯粹要求了解常识性术语 | 模型可直接回答，不强迫调用工具 |
| R04 | 工具③返回了有来源的标准数据 | 模型正确解释数据及适用范围，不当成用户已确认配置 |
| R05 | 工具③或④不可用/超时 | 结束无效循环，透明说明阻断并继续可完成的需求交流 |
| R06 | 同参数同工具重复调用且没有新信息 | 预算/重复调用防护阻止无穷循环 |
| R07 | 工具预算耗尽 | 不伪称未完成的工具动作成功；给出已有可信结果和下一步 |
| R08 | 用户修改参数与根据新参数推荐 | 写入工具串行执行；查询/推荐必须引用正确 revision |
| R09 | 用户打断原本需求收集，询问材料再要求继续 | 能改变任务焦点并回到缺项，而不是固定问卷 |
| R10 | 模型尝试调用未经暴露的第六工具（例如优化器） | 工具执行层拒绝；不产生优化或求解副作用 |

初期每轮约 5–6 次业务工具调用为**可配置建议预算**，不是强制每轮都调用这么多。真实测试记录工具数量、模型调用次数与中断恢复情况，不记录或展示模型私有思考文本。

## 5. 必须始终满足的工程不变式

1. 工具①是**唯一**参数写入入口；确认必须由服务端用户证据/有效已展示提案支持，不接受 LLM 自报。
2. `null` 与 `0` 严格区分；approximate/range 不悄悄变精确值；用户锁定的优化槽不被覆盖。
3. 工具②只报告客观需求状态；**模型负责问什么、怎么问**，但不得擅自更改 V1 必需项集合。
4. 工具③的搜索结果不自动等于审核的工程数值；工具④不能无依据推荐。
5. 推荐提案与用户已确认参数分开；工况修改后相关适用性失效；无效旧提案不能被接受。
6. 写入受 revision/request_id 保护，写入与依赖查询不乱序；会话 history 不是另一套可信参数事实。
7. 需求完成、整份 Brief 用户确认、RoBAS TEMPLATE_READY、RUNNABLE_READY 不互相冒充。
8. 工具⑤允许 draft 导出，不完整时不标 completed；PR-06 前无法确认 RoBAS 324 字段模板就绪。
9. 工具失败/预算耗尽必须可解释退出，不能静默填系统默认、制造不存在的适用性证据。
10. 数据集与 Agent 使用同一版本的 DGBDesignBrief 参数名、类型、单位；同任务不同话术不得跨训练与测试拆分。
