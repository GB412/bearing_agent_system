# 深沟球轴承设计任务数据集 · V2（24 条）

## 这是干什么的？

每个 `case_id` 有**一条完整的结构化设计任务**和**一段包含所有用户层设计输入的自然语言**；不预先写 Agent 的多轮回复。用自然语言测试“需求提取 → 校验 → 结构化 DesignBrief”，将输出与结构化任务逐字段比较。**任务中的工程物性由 RoBAS 原始资源提供，不要求用户在自然语言中背诵。**

这些是**人工合成的工况及设计目标**，不是实测设备案例或已求解的最优轴承。所选 RoBAS 型号、材料名称、润滑名称及相应原始物性已对给定资源包逐条精确核验。**没有一条案例获得工程组合适用性批准或 RoBAS 求解验证。**

## 文件组织

- `data/design_cases.jsonl` — 24 条结构化任务，包含型号、尺寸、负载转速、温度、工程配置、需求约束、五变量优化设置及**实际原库物性快照**。
- `data/user_requests.jsonl` — 24 条自然语言长输入，每条对应一条设计任务。无固定剧本。
- `schema/DGBCase_v2.schema.json` — 两类 JSONL 的结构、类型、基础范围约束。
- `review/case_review.csv` — 24 条便于人工快速查看、筛选的审核索引。
- `README.md` — 本说明。
- `scripts/generate_dgb_cases_v2.py` — 从用户提供的 RoBAS ZIP 重新读取材料/油品/型号并确定性生成 24 条数据。
- `scripts/validate_dgb_dataset.py` — 校验 Schema、设计任务与自然语言关联、数值一致性；传入原始 ZIP 时再次核对型号/物性/来源 SHA。

## 数据的含义与质量边界

1. `dimensions` 是固定外形，**不代表参考型号的内部滚动体几何必须照搬**。不同型号实际存在于同一个 `DGBData.db` 的 `model` 表。
2. `operating` 中的速度、载荷、假定轴承温度都是**合成用户设计条件**。单个轴承的 Fr/Fa，不是整机总载荷。此版全部为内圈旋转、外圈固定的单工况；型号、速度大小、载荷大小和 Fa=0/非零有明显变化；不要声称已经覆盖全部实际工况类型。
3. `engineering` 中材料名称、油品名称与 RoBAS CSV 的自然键**一致且能精确匹配**；`robas_data.materials` 和 `.lubricants` 保存选中的各条原始数值及原 CSV 行号，不只是一个引用。`robas_data.sources` 保留源文件 SHA-256。因档案较大且涉及权限，不上传原始数据库、原始 ZIP 或商业二进制。
4. 已使用材料名称：`氮共渗轴承钢`、`渗碳轴承钢`（圈/球的候选），以及 `工具钢`（保持架候选）。润滑油：`VG22`、`VG32`、`VG46`、`VG68`、`VG100`。**尤其“渗碳轴承钢”原库个别物性（如线膨胀系数）需要专业核对；该数据保持原样，不自动替换成常识值。** 数据库值存在 ≠ 用于真实计算可靠。
5. 保持架 `StampingCage` 在此前审阅的 RoBAS DGB 源码中可找到实现，但**材料和高速适用性未审核**；CN/C3 的实际数值映射和 k5/m5/H7 配合适用性均未冻结；初始径向游隙值保持 `null`。
6. `requirements` 包含 **用户希望满足的性能目标和硬约束**：最小功耗、最大寿命、最小温升、最小峰值接触压力、最大径向刚度；约束的数值全是合成用户需求，**不表示计算支持或物理可行**。`optimization.locked.Z` 只在 RoBAS `主参数` 对应型号存在记录时使用真实参考 Z，`optimization.bounds` 是用户假设的区间，尚未工程审查。
7. `quality.catalog_verified=true` **仅针对型号、材料、润滑目录记录和数值一致性**；全部案例 `engineering_reviewed=false`、`solver_verified=false`。绝不能直接作为五参数优化的性能真值、真实合格方案、可执行 DATA.txt。
8. 全部参数为固定分析点；当前不测试单轮自然语言中的“未知/范围”的情况。后续需要考察动态追问时，应单独设计缺项输入，不应把完整用户输入当成多轮对话能力的证据。

## 如何本地验证

要求 Python 3.11+、`jsonschema`（`python -m pip install jsonschema`），以及需要复核原库时可访问的 `RoBAS_Resources.zip`。

```bash
# 只校验结构、来源快照的内部一致性以及 24 条 ID/自然语言对应关系
python scripts/validate_dgb_dataset.py

# 重新对原始 RoBAS CSV/SQLite 逐条校验名称、数值、文件哈希与已锁定的参考 Z
python scripts/validate_dgb_dataset.py --robas-archive /path/to/RoBAS_Resources.zip

# 如需重复生成本批样例（会覆盖五文件数据中的三份：design / requests / review）
python scripts/generate_dgb_cases_v2.py --robas-archive /path/to/RoBAS_Resources.zip
```

**使用原则：** 只把 `user_requests.jsonl[*].text` 作为被测 Agent 的输入，`design_cases.jsonl` 是隐藏的标准业务值参考。评估字段时应根据现有 `DGBDesignBrief/v1` 合同映射比较，不要要求测试输出保存同样的 CSV 证据快照。后续对真实方案做校核时，应先做工程配置/模型适用性审核，再运行实际 RoBAS 计算获取可靠性能标签。
